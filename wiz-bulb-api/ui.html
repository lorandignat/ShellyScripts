API

Every bulb is addressed by its MAC. Use the MAC without separators in URLs (9877d50abae0); the button under each card copies it.

MethodPathPurpose
GET/bulbs Cached list of all bulbs. Add ?live=1 to probe them first.
GET/bulb/<mac> Strict live check: 200 when the bulb answers, 503 when not. Used by Shelly.
GET/bulb/<mac>/state Power state plus colour: state, dimming, r/g/b/c/w, temp, sceneId.
POST/bulb/<mac>/toggle Flip power. Returns the new state.
POST/bulb/<mac>/on Turn on.
POST/bulb/<mac>/off Turn off.
POST/bulb/<mac>/set Raw setPilot with a JSON body: dimming, temp, r/g/b, sceneId…
POST/bulb/<mac>/category Assign a category: {"category": "<id>"}, or null to clear.
DELETE/bulb/<mac> Forget a bulb. It is re-added automatically if it appears on the LAN again.
GET/categories Categories with bulb counts.
POST/categories Create one: {"name": "Bedroom"}.
DELETE/categories/<id> Delete a category; its bulbs become uncategorised.
GET/healthz {"ok": true} when the service is running.

Status fields

present — on the LAN (TCP check every 60 s).
responsive — answered UDP within the last 60 s.
Unreachable bulbs answer 503 with {"online": false}.

Examples

curl -s http://192.168.1.5:8077/bulbs?live=1

curl -s http://192.168.1.5:8077/bulb/9877d50abae0
curl -s -X POST http://192.168.1.5:8077/bulb/9877d50abae0/toggle
curl -s -X POST http://192.168.1.5:8077/bulb/9877d50abae0/set \
     -d '{"dimming": 40, "temp": 2700}'

# Shelly: 200 = bulb is reachable right now
curl -s -o /dev/null -w "%{http_code}" \
     http://192.168.1.5:8077/bulb/9877d50abae0

Known bulbs, their categories and manual removals are stored in /data/state.json, so an offline bulb stays visible until you remove it.

If WIZ_API_TOKEN is set, send Authorization: Bearer <token> with every request.
